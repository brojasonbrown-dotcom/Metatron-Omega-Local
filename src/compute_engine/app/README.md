# METATRON Ω — Toroidal Brain Interface

A secure Electron desktop interface to the **certified toroidal RHUFT brain**
(`../omega`). Every answer is **computed live** from the running engine — there
is no canned text, no mock LLM. The responder reads the live `HostSnapshot` and
the host's structural views (`describe / web / spectral / memory / cognition /
learn`) and reports what the brain actually holds.

## What the brain honestly is

The live service is the certified `MultiTorusEngine` (18-rung dense core),
driven by `EngineHost` at a wall-clock cadence. The host's `pump()` advances the
engine a fractional number of ticks per slice so the measured tick rate matches
the target Hz under load, and its sensory plane resolves once per web tick so
every rung reads the same sensory instant (Jacobi discipline). Every reported
number — coherence, energy, flux, rung telemetry, braid memory, cognition — is
the host's own snapshot, computed each tick.

## The floating buttons

- **⏻ engine** — starts/stops the live brain loop. The button glows while the
  loop runs; state is never faked.
- **Σ panel** — collapses/expands the telemetry column (open by default). The
  column is a permanent right-hand panel: coherence, energy, flux, rung ladder,
  spectral view, braid memory, cognition, plus sensor drives — all computed
  live each tick. Drag the divider to resize it (width persists).

## The LLM instrument (OpenRouter / DeepSeek)

The Ω brain is always the default answerer. The instrument row at the top of
the Σ panel holds an OPTIONAL external instrument with two providers:

- **openrouter** (default) — one universal key (`OPENROUTER_API_KEY`) that
  serves DeepSeek (`deepseek/deepseek-chat`, `deepseek/deepseek-r1`) and
  thousands of general models at `api.openrouter.ai`.
- **deepseek** — DeepSeek's native API (`DEEPSEEK_API_KEY`) at
  `api.deepseek.com` (`deepseek-chat` / `deepseek-reasoner`).

Pick the provider, optionally type a model id (empty = a sensible default),
paste the matching API key, then click **set** and the **LLM** square to
toggle it on. Keys, provider and model persist via `setx` (HKCU). While on,
chat messages are answered externally with the brain's live state in view and
arrive in a distinct gold bubble — an external answer can never be mistaken
for a brain computation. Click again to return to the Ω brain.
- **🎙 mic** — live microphone: 100 ms windows at the device's native rate,
  projected onto φ-spaced Goertzel bands in the main process; the measured
  energy drives the brain loop. Absent/denied device → honest error flash.
- **📷 camera** — live camera: 144×89 (F_12×F_11) luminance grid at 2 Hz,
  golden-spiral mode projection; mean luminance drives the loop.

## How METATRON Ω answers — no mocks, no hallucination path

1. **Meta-questions** (`status · ladder · web · spectral · memory · mind ·
   learn`) are read directly from the live `HostSnapshot` and the host's
   structural views — numbers win.
2. **Free text** is encoded into the sensory plane and the brain advances — the
   honest learning path. What you say becomes part of the field; the reply
   reports the change in coherence, energy, novelty, concepts and digest.

There is no fake intelligence here: if the brain can't compute something, the
responder says so and lists what it can do.

## Run (development)

```bash
npm install          # once (electron binary)
npm start            # bundle the omega brain + open the window
npm run smoke        # headless: brain loop + responder + sensory (no GUI)
npm run smoke:gui    # end-to-end: window loads, IPC roundtrip, auto-quit
npx electron . --shot=ui.png   # hidden window → capture a PNG of the UI → quit
```

**Note (IDE terminals):** if your terminal exports `ELECTRON_RUN_AS_NODE=1`
(some Electron-based IDEs do), Electron silently behaves as plain Node and the
app won't start. Prefix with `env -u ELECTRON_RUN_AS_NODE` (Git Bash) or run
from a plain terminal.

## Package (Windows .exe)

**Double-click (recommended):**

- `BUILD-OMEGA.bat` — full pipeline: deps check → omega bundle → smoke checks →
  pack → packaged `--ci` verification → NSIS installer + portable. Stops loudly
  at the first red step.
- `LAUNCH-OMEGA.bat` — starts the fresh build in `release\win-unpacked\` if one
  exists, else the installed app, else the dev app from source.

Both clear `ELECTRON_RUN_AS_NODE` internally, so they work correctly even from
IDE terminals that export it. **Do NOT launch `release\*.exe` directly from an
IDE terminal** — the IDE exports `ELECTRON_RUN_AS_NODE=1`, which silently turns
the exe into plain Node: the process exits instantly and no window opens. Either
use `LAUNCH-OMEGA.bat`, double-click the exe in Explorer, or run
`set ELECTRON_RUN_AS_NODE=` first in that terminal.

**Manual equivalent:**

```bash
npm run icon         # regenerate build/icon.ico (PIL; phosphor torus ring)
npm run pack         # unpacked build → release/win-unpacked/METATRON-OMEGA.exe
npm run dist         # full build → release/METATRON-OMEGA-1.0.0-setup.exe (NSIS)
                     #              + release/METATRON-OMEGA-1.0.0-portable.exe
npm run verify:dist  # run the packaged exe with --ci (IPC + brain roundtrip)
```

The installer is an assisted NSIS setup (install-dir selectable, per-user,
"METATRON-OMEGA" shortcut). The portable exe runs from anywhere with no
installation. Both ship the complete app: Electron runtime + renderer + the
bundled omega brain — no network, no external services required on the target
machine.

**Verification:** the packaged and portable executables accept `--ci` and must
print a PASS report. Silent install for testing:
`METATRON-OMEGA-1.0.0-setup.exe /S /D=C:\path\to\dir`.

**Unsigned binary:** no code-signing certificate is configured, so Windows
SmartScreen will warn on first run ("unknown publisher"). That is expected for a
local build — the binaries are byte-identical to what `electron-builder`
produced from this tree. Sign with a real certificate (`win.certificateFile`)
before distributing widely.

## Design rules (inherited from CORE_VISION)

- **Real computation only** — if the brain can't compute it, the responder says
  so and lists what it can do. There is no fake intelligence here.
- **Minimal interference** — vanilla renderer, one IPC channel, one bundle step,
  no framework churn. The strongest method is the one that is already proven:
  the certified engine itself.
