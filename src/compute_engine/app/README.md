# AVA — RHUFT Engine Desktop Interface

A clean Electron chat UI whose every answer is **computed live from the RHUFT
18-stable-scale engine** (`../engine`). No canned facts, no mock LLM: the
responder parses the message, runs the engine's real modules (scaleTable,
lucas, closureResidual, memoryKernel, selfMeasurement, densityField), and
reports the result with its provenance.

## Layout

```
electron/
  main.cjs          canonical secure-window pattern (Electron's own default_app
                    model): context-isolated + sandboxed renderer, show:false →
                    ready-to-show, navigation locked, window.open denied,
                    permissions: ONLY mic/camera and ONLY for the local page,
                    single-instance lock, IPC (chat + engine loop + sensors)
  preload.cjs       the only bridge: window.ava.{send, engine, sensorAudio, sensorVideo}
  responder.cjs     the chat brain — intent router over live engine calls
  engineLoop.cjs    LIVE simulation service: 64-node ring, MemoryKernel +
                    Propagator (engine's own files 9/10), 4 invariants computed
                    per tick; sensor drives enter via the conservative
                    dampedRegularization path only
  sensory.cjs       measurement → field codec, ported from v14 signal_codec:
                    Goertzel φ-bands (audio), golden-spiral modes (vision),
                    28-element unit-norm fields. Resolution upgraded:
                    48 kHz-native audio, 144×89 (F_12×F_11) vision grid
  engine-entry.ts   the engine surface the app uses (bundled)
  engine-bundle.cjs GENERATED by npm run bundle:engine (do not edit)
renderer/
  index.html        CSP-locked page (default-src 'self')
  styles.css        phosphor-terminal ("matrix") theme + scanlines
  rain.js           subtle matrix-rain canvas (pauses when hidden)
  chat.js           classic chat loop (vanilla DOM, no framework)
  sensors.js        mic (AnalyserNode fftSize 8192, 100 ms frames) and camera
                    (144×89 luminance, 2 Hz) capture — measurement ONLY
  fab.js            the 4 floating buttons: ⏻ engine · Σ stability · 🎙 · 📷
scripts/
  bundle-engine.mjs bundles the engine with the esbuild already in engine/node_modules
  make-icon.py      generates build/icon.ico (PIL; phosphor torus ring)
  smoke.mjs         headless test: chat + sensory codec + engine loop (28 checks)
```

## The four floating buttons

- **⏻ engine** — starts/stops the live engine loop (real wave on a 64-node
  ring, ν=0.5, ticked ~30 Hz in the main process). The button glows while
  the loop runs; state never faked — it always reflects `engineLoop.state()`.
- **Σ stability** — slides out the FRAMEWORK STABILITY panel: the four
  invariants computed live each tick (coherence = cos² self-overlap,
  closure defect = net-flux fraction, drift = naive-energy deviation with the
  measured 1e-3 bound, burden = Σu²), sensor drive levels, and the exact
  certificates (λ=φ⁻², roots {1,−φ⁻²}, ν* = 3/2).
- **🎙 mic** — live microphone: 100 ms windows at the device's native rate,
  projected onto 14 φ-spaced Goertzel bands in the main process; the measured
  energy drives the engine loop (button glow tracks the level; title shows
  the dominant φ-band). Absent/denied device → honest error flash.
- **📷 camera** — live camera: 144×89 luminance grid at 2 Hz, golden-spiral
  mode projection; mean luminance drives the loop; small preview bottom-left.

The sensory mathematics is the v14 brain's signal_codec, ported and upgraded
(v14: 16 kHz mic / 89×55 screen grid → AVA: native-rate audio / 144×89 grid).


## Run (development)

```bash
npm install          # once (electron binary)
npm start            # bundle engine + open the window
npm run smoke        # headless: responder answers real queries (no GUI)
npm run smoke:gui    # end-to-end: window loads, IPC roundtrip, auto-quit
npx electron . --shot=ui.png   # hidden window → capture a PNG of the UI → quit
```

**Note (IDE terminals):** if your terminal exports `ELECTRON_RUN_AS_NODE=1`
(some Electron-based IDEs do), Electron silently behaves as plain Node and
the app won't start. Prefix with `env -u ELECTRON_RUN_AS_NODE` (Git Bash) or
run from a plain terminal.

## Package (Windows .exe)

```bash
npm run icon         # regenerate build/icon.ico (PIL; phosphor torus ring)
npm run pack         # unpacked build → release/win-unpacked/AVA.exe
npm run dist         # full build → release/AVA-0.1.0-setup.exe (NSIS installer)
                     #              + release/AVA-0.1.0-portable.exe (no install)
npm run verify:dist  # run the packaged exe with --ci (IPC + engine roundtrip)
```

The installer is an assisted NSIS setup (install-dir selectable, per-user,
"AVA" shortcut). The portable exe runs from anywhere with no installation.
Both ship the complete app: Electron runtime + renderer + the bundled engine
— no network, no external services required on the target machine.

**Verification:** the packaged, portable, and silently-installed executables
all accept `--ci` and must print
`[ci] renderer+IPC+responder roundtrip: PASS`.
Silent install for testing: `AVA-0.1.0-setup.exe /S /D=C:\path\to\dir`.

**Unsigned binary:** no code-signing certificate is configured, so Windows
SmartScreen will warn on first run ("unknown publisher"). That is expected
for a local build — the binaries are byte-identical to what
`electron-builder` produced from this tree. Sign with a real certificate
(`win.certificateFile`) before distributing widely.

**What is NOT inside:** the `brain v14` autonomous mind layer (Ollama
phi/mathstral, 5.4 GB model blobs, mic/screen sensors) is a separate system
and is deliberately not packaged. AVA-the-app talks only to the RHUFT
18-scale engine, which is fully self-contained.

Try in the chat: `help`, `scale 13`, `closure 13`, `lucas 27`, `fib 100`,
`phi`, `ladder`, `torus 27`, `memory`, `overlap`, `density`, `status`.

## Design rules (inherited from CORE_VISION)

- **Real computation only** — if the engine can't compute it, the responder
  says so and lists what it can do. There is no fake intelligence here.
- **Minimal interference** — vanilla renderer, one IPC channel, one bundle
  step, no framework churn. The strongest method is the one that is already
  proven: the engine itself.
